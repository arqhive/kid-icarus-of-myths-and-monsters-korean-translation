# ROM 및 한글화 구조

## 원본과 뱅크

원본은 128 KiB, 16 KiB 뱅크 8개, MBC2 + 배터리(타입 06)입니다. 결과는 256 KiB/16뱅크이며 헤더 크기 코드는 03으로 바꿉니다. 모든 새 뱅크의 마지막 바이트에는 뱅크 번호를 기록합니다. 게임의 호출 보조 코드가 7FFF를 읽어 이전 뱅크를 복원하기 때문입니다.

| 새 뱅크 | 용도 |
|---|---|
| 8 | 원본 뱅크 5 복사본, 독립 오프닝 글꼴과 한글 오프닝·메뉴 맵 |
| 9 | 원본 뱅크 7 복사본, 한글 타이틀 저위 타일(원본 ™ 타일 복원) |
| 10 | 대사별 1bpp 글꼴(페이지당 256바이트), 음절표(6800), 대사 출력 루틴(7400) |
| 11 | 마지막 엔딩 문구 전용 맵과 글꼴 |
| 12 | 남은 기회·게임 오버 화면 전용 UI 글꼴 |
| 13 | 스테이지 UI 글꼴. 원본 뱅크 2에서 미사용 가타카나 F2–FD만 교체, 상태창 글자(7E00) |

## 일반 대사

포인터 테이블은 ROM 17918–17965, 원본 대사는 17966–17FEF에 있습니다. 39개 포인터의 순서와 FD/FF 제어 의미를 유지합니다. 번역 문자열은 같은 데이터 영역에 재배치하며 포인터를 갱신합니다.

한국어는 받침을 아래 타일로 분리합니다. 위 타일은 Galmuri7의 받침 없는 음절(초성+중성), 아래 타일은 `tools/hangul_stack.py`에서 그린 받침입니다. Galmuri7은 받침을 세 줄에 눌러 그려 `을`이 `운`처럼 보이기 때문입니다.

대사 바이트는 페이지별 음절 번호 1–31, 공백 00, 줄바꿈 FE, 원래 종결 제어 FD/FF입니다. 뱅크 10의 6800+페이지×64에 음절별 위 타일 칸(0–31)과 받침 칸(32–63, 0은 없음)을 둡니다. 위·받침 글꼴은 합쳐 페이지당 26칸이며, 원래 알파벳 타일 94–9F, A4–B1을 씁니다. 최대 18칸 × 3줄이고 가운데 맞춤합니다.

줄바꿈은 맵 두 줄씩(1788C: +40) 내려가고, 일반 대사는 9927에서 시작합니다(0F30). 대사 상자 지우기는 9927부터 여섯 줄입니다(178D3). 체력 증가 장면은 원래대로 98E7에서 시작합니다.

ROM 178A3의 원래 효과음 호출을 고정 뱅크 0063의 진입 코드로 연결합니다. 진입 코드는 뱅크 10의 7400 루틴을 부릅니다. 루틴은 위 글자와 받침 글자를 VRAM 접근 가능 상태를 기다려 올리고, 맵의 현재 칸과 바로 아래 칸에 직접 씁니다. BGP 93에서는 저위 비트면만, E1에서는 두 비트면을 써 일반 대사와 엔딩의 색상을 맞춥니다. 뱅크 5를 복원하고 원래 효과음을 호출합니다.

## UI와 그래픽 글자

뱅크 2의 8800 글꼴 블록은 스테이지 스프라이트와 겹칩니다. C7–CE는 힌트 방 NPC, D0–EE와 F0–F1은 테두리·사물이고, 비어 있는 칸은 가타카나 F2–FD뿐입니다. v0.1은 C7–CE, E5–FE에 글자를 넣어 힌트 방 NPC 머리가 `세요`로 나왔습니다.

- 스테이지 로더(15B4)는 뱅크 13을 올립니다. 결과·저장 화면 글자 12자는 F2–FD에 있습니다.
- 상태창 글자 8자는 창을 그리는 17610에서 뱅크 13의 7E00을 알파벳 타일 94–9B에 올린 뒤 그립니다. 상태창과 대사는 함께 나오지 않습니다.
- 남은 기회·게임 오버 화면(388B)은 뱅크 12를 올립니다. 이 화면 전용 글자는 C7–CE, E5–EB에 있습니다.
- 상태창 `구역`·`공격력`은 왼쪽 맞춤입니다(`ko.json`의 `align`).

PUSH START 및 GAME OVER는 4바이트 OAM 메타스프라이트 레코드이며 텍스트 바이트 배열과 별도로 처리합니다. PAUSE는 71A1–71F0의 전용 다섯 타일이므로 이를 `일시 정지`로 교체합니다. 마지막 엔딩 표기는 0CE7에서 뱅크 11의 글꼴과 맵을 불러옵니다.

타이틀은 Galmuri11 글립을 확대해 원본 영역의 타일을 다시 만들고, 부제는 받침이 읽히도록 Galmuri9로 그립니다. 원본 ™ 타일은 같은 자리(3행 19열)에 다시 그립니다. 로고 바깥 타일과 스크롤이 추가로 읽는 공백 타일 4E는 유지합니다. 원본 Nintendo 상표·저작권 표기는 유지합니다.

## 데이터 관리

Git에는 도구, 한국어 번역, 문서와 폰트 라이선스만 넣습니다. 원문·분석 덤프·화면·세이브·ROM·IPS·ZIP은 로컬 생성물입니다. IPS에는 추가 뱅크의 데이터도 포함되므로 별도 완성 ROM 없이 원본에 적용됩니다.

빌드는 원본 SHA-256을 검사하고 헤더 및 전체 체크섬을 다시 계산합니다. 배포 패처는 원본·IPS·결과 해시를 모두 검사합니다. 검증 결과의 해시가 현재 ROM과 같아야 배포 ZIP을 만들 수 있습니다.
